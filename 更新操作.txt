【加图上线：四步】

第 1 步  把新图放进 raw_photos\
         文件名 = 作品名，例如  纱夜 (12).png
         支持 .png / .jpg / .jpeg / .webp
         同名文件不要重复

第 2 步  打开命令行，逐行复制粘贴：

            cd /d D:\website\MyGallery

            C:\Users\cqc\.workbuddy\binaries\python\envs\default\Scripts\python.exe build_gallery_v3.py

         这一步会自动完成：
             · 压缩新图为 site\images\*.webp       （灯箱大图）
             · 生成缩略图 site\thumbs\*.webp        （列表页只加载这个）
             · 复制原图到 site\originals\           （下载按钮给的就是它）
             · 重新生成 site\index.html

第 3 步  提交并上线：

            git add .
            git commit -m "更新：新增 N 张作品"
            git push origin main

         推送后 Cloudflare 自动部署，约 1~2 分钟生效。

第 4 步  刷新 https://haorenyige.top 确认


--------------------------------------------------------
 必须知道的几件事
--------------------------------------------------------

[1] raw_photos\ 现在已被 .gitignore 忽略，不再进版本库。
    所以 git add . 是安全的，不会再误把 768 MB 素材推上去。
    它的内容与 site\originals\ 逐字节一致（320/320 同源），
    仓库里已有完整备份，删了也能恢复。

[2] 缩略图全自动生成，不用管。
    列表页用 560px 缩略图（平均 36 KB），点开才加载原始大图
    （平均 151 KB）。整页载荷因此降了约 76%。

[3] 下载按钮给的始终是 site\originals\ 里的 PNG 原图，
    没有做任何重编码，和以前一样。

[4] 作品名会自动分成系列标签：
        「僵尸 (1)」「僵尸 (2)」   ->  系列「僵尸」
        「shaye__02392_」          ->  系列「shaye」
        「酒吞_00389_」            ->  系列「酒吞」
        「外冷内？2」              ->  系列「外冷内？」
        裸名（如「滑板.png」）      ->  独立单张，不进标签栏
    同一系列满 2 张才会出现在标签栏。所以取名尽量一致：
    现在「外卖打翻2」和「打翻外卖1/3/4/5/6/7」被当成了两个
    系列，前者落单没有标签——改个名就能合并。

[5] git push 如果卡住很久不出声：
    本机的凭据助手在非交互环境取不到账号，属于已知问题，
    换下面这行即可（不改动你的任何配置）：

        git -c credential.helper= -c credential.helper=wincred push origin main


--------------------------------------------------------
 想先预览、不上线
--------------------------------------------------------

生成一个预览子站，正式首页完全不动，两者并存：

    ...\python.exe build_gallery_v3.py --out site\beta\index.html --beta

然后照常 add / commit / push，访问：

    https://haorenyige.top/beta/

--beta 会自动改用根路径资源、加 noindex（不被搜索引擎收录）、
并在顶部加一条返回正式版的链接。看满意了再执行：

    ...\python.exe build_gallery_v3.py        （生成到正式首页）
    git rm -r --cached site\beta              （下线预览）

 访问统计（只有你能看到）
========================================================

统计什么
    · 访问量 PV / 独立访客 UV
    · 每张作品的下载点击次数排行
    （按你的选择，不做作品查看排行、不做搜索词、不做来源）

数据在哪
    页面只负责"上报"，上报接口是只写不读的——别人打不开它，
    页面上也不显示任何数字。原始数据存在你 Cloudflare 账号的
    KV 里，只有在本地跑脚本才拉得下来。

怎么取数据（在项目根目录执行）

      python stats\pull_stats.py

    第一次会让你粘贴读取密钥（输入时屏幕不显示），之后自动记住。
    输出到：

      stats\reports\日期-统计报表.md      <- 直接看这个
      stats\reports\日期-按天.csv
      stats\reports\日期-下载排行.csv
      stats\data\events.jsonl             <- 原始事件存档，只增不减

    脚本是增量的：每次只拉新增事件，按事件唯一 id 去重，
    重复运行不会重复计数、不会把存档撑大。

其他参数

      --full                 从最早重拉一遍（去重，不会翻倍）
      --from 2026-10-01      指定起点
      --set-key              换了密钥后重新输入
      --report-only          只用本地已有数据出报表，不联网

隐私说明（你自己心里有数就行）

    · 不存 IP、不存浏览器标识、不用 Cookie
    · 访客标识 = SHA-256(IP + 浏览器标识 + 当日密钥) 的前 12 位，
      每天重新生成、无法反推，所以只能当天去重
    · 上报失败绝不影响页面显示（失败就静默丢掉）
    · 天数按东八区切分

⚠ 统计数据目录已在 .gitignore 里（stats\.secret、stats\data\、
   stats\reports\）。这个仓库是公开的，这些千万别提交。

关掉统计
    重新生成页面时加 --no-track 即可：
      ...\python.exe build_gallery_v3.py --no-track
    （--beta 预览模式本来就不埋点）
